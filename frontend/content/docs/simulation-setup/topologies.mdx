## The idea
 
In a real village, not everyone interacts with everyone. You talk to your neighbours,
your family, the people at work. A disease spreads along those links, and so does gossip.
 
A **topology** is the map of those links. It decides who counts as an agent's
**neighbours**. When a rule asks "how many of my neighbours are ill?", the topology
decides whose health is checked.
 
<Callout title="In short" type="info">
You choose one of three kinds of topology: **everyone knows everyone**
(`all_pairs`), **a random handful** (`random_sample`), or **a network of
connections** (`network`).
</Callout>
## Which one should I pick?
 
<Cards>
  <Card title="all_pairs: a small town meeting">
    Everybody is a neighbour of everybody else. The simplest choice, and right for small
    populations where everyone really does mix.
  </Card>
  <Card title="random_sample: bumping into people">
    Each agent meets a random handful each step, like people in a busy street. Right
    when contacts are casual and change all the time.
  </Card>
  <Card title="network: a web of friendships">
    Each agent has a fixed set of connections, like friends and family. Right when who
    you know matters, and stays the same.
  </Card>
</Cards>
## Setting up a topology
 
Topologies live in the `topologies` section of the configuration. Each one has a name
you choose, and the list can't be empty. You use the name later in your rules.
 
```json
"topologies": {
  "contact": { "mode": "all_pairs" },
  "street": { "mode": "random_sample", "k": 5 },
  "friends": {
    "mode": "network",
    "graph": { "type": "erdos_renyi", "n": 1000, "p": 0.05 }
  }
}
```
 
Every topology also accepts `agent_types`. List agent types in it to limit the
neighbours to those types, such as `["predator", "prey"]`. Leave it out for everyone.
 
### everyone knows everyone
 
```json
"contact": { "mode": "all_pairs" }
```
 
Each agent has every other agent as a neighbour. By default, agents are not their own
neighbours. To change this, add `"allow_self_interaction": true`.
 
<Callout title="Watch the size" type="warn">
With 1,000 agents there are almost a million pairs, and with 10,000 agents there are
almost a hundred million. For large populations, `random_sample` or `network` is
usually a better fit.
</Callout>
### a random handful
 
Choose **either** a fixed number of neighbours **or** a share of the population. Giving
both, or neither, is rejected.
 
```json
"street": { "mode": "random_sample", "k": 5, "seed": 42 }
```
 
*"Each step, every agent meets 5 random agents."*
 
```json
"crowd": { "mode": "random_sample", "proportion": 0.1 }
```
 
*"Each step, every agent meets 10% of the population."*
 
The optional `seed` makes the random choices repeatable.
 
<Callout title="Good to know" type="info">
Agents are picked *with replacement*. The same agent can turn up twice in one
neighbour list. If `k` is larger than the number of agents available, you simply get
as many picks as there are available agents, and no error.
</Callout>
### a network of connections
 
You can either generate a network, or bring your own.
 
**Generate one.** Choose a kind of network that matches how people connect:
 
| `type` | In plain words | Settings |
|---|---|---|
| `erdos_renyi` | Friendships form at random. Any two agents may be linked. | `n` agents, `p` chance of a link |
| `barabasi_albert` | A few popular agents have many links, most have few. | `n` agents, `m` links for each newcomer |
| `watts_strogatz` | Tight local circles, with a few long-distance links. | `n` agents, `k` nearest neighbours, `p` chance of rewiring |
 
```json
"friends": {
  "mode": "network",
  "graph": { "type": "watts_strogatz", "n": 1000, "k": 6, "p": 0.1, "seed": 7 }
}
```
 
**Bring your own.** If you already have a graph file, point to it:
 
```json
"friends": { "mode": "network", "graph": { "source": "path/to/my_graph.graphml" } }
```
 
Connections in a network are two-way. If A is linked to B, then B is linked to A.

## Using a topology in a rule
 
When you have **one** topology, rules use it automatically. When you have **two or
more**, every rule that looks at neighbours must say which one, with `topology_name`:
 
```json
{
  "field": "energy",
  "expression": "state['energy'] + 0.1 * neighbor_mean('energy')",
  "topology_name": "friends"
}
```
 
Forgetting it is an error, not a silent guess. See
[Behaviour Expressions](/docs/behaviour-expression#looking-at-neighbours).
